准备第一次真实比较

服务启动后，还需要参考音色、场景噪声、降噪算法和评测模型。首页会逐项检查；全部就绪后，才开始比较内置 V1 与 V2。

这条路径会产生真实推理结果。MiniMax 音色生成需要你自己的账号与额度；先预览调用量，再决定是否生成。没有密钥和模型时，可浏览工具与生成语料，但不能完成真实质量评测。

参考音色场景噪声降噪算法评测模型完成比较

1. 建立 26 个参考音色

  1. 在项目根目录把 .env.example 复制为 .env，填写自己的 MINIMAX_API_KEY 与 MINIMAX_GROUP_ID，然后重启服务。不要公开这个文件。
  2. 进入 TTS 合成 → “准备测试音色”。已有完整缓存时优先选择缓存；否则填写资源标签，固定 26 个普通话系统音色、seed 42。
  3. 先点“预览调用量”，检查固定探针与音色列表，再明确确认生成。显示的是调用上限，缓存会减少实际调用，并非精确金额。任务可请求暂停，已有成功音频保留；部分缓存可“预览续跑”后明确确认补齐。
  4. 选择缓存进入 声线聚类，确认“四簇聚类”，检查分布，再确认“锁为声线参考集”。服务端要求 26 个完整且不同 voice_id，并覆盖 C1–C4。资源锁定不会晋级降噪版本；失败样本先补齐，噪声和模型也须分别就绪。

10、25、50、100 个音色用于独立声线分析，不能锁为此固定基准。旧目录模式可以分析已有 WAV，但目前不能仅靠一个任意 WAV 文件夹直接建立这套固定基准。

2. 放置六个场景的正式噪声

准备你有权使用、与场景相符的 WAV 录音，分别放入以下目录。每个目录至少一段可解码的 WAV：非空、采样率 8–48 kHz、时长不少于 0.25 秒。程序会按设定 SNR 混音。文件能打开，只说明它可以进入实验，不证明它是实验室认证录音。

  • 安静 · 公园：data/noise/demand/NPARK/
  • 办公室：data/noise/demand/OOFFICE/
  • 咖啡厅：data/noise/demand/PCAFETER/
  • 食堂：data/noise/demand/PRESTO/
  • 路口 · 交通：data/noise/demand/STRAFFIC/
  • 地铁 · 高噪：data/noise/demand/TMETRO/

bootstrap_demo.py 生成的合成布线素材不能进入正式基准。程序按文件内容哈希识别，改名复制同样会被拒绝。若运行过这个脚本，请把这些文件移到正式噪声目录之外，再准备真实场景素材。空文件、损坏 WAV 或布线素材混放时，该场景都不会显示就绪。

来源未知但可解码的录音可以用于跑通流程，首页会标记为「来源未声明」，不会写成已认证。若要记录用途与来源，把 docs/asset_manifest.example.json 复制为 data/noise/asset_manifest.json 并填写；声明来源仍不是科学认证。

首页「资产已检测到」只表示四项文件/依赖在本机；「真实推理」要等本机出现过真实评测记录。两者分开，检测到 checkpoint 不等于已经跑通 AudioBox。MiniMax 只在你主动生成 Cohort 且预览成本之后才会调用。

“无预览”与“没有噪声源文件”是两种状态。预览文件位于 data/noise/preview/场景ID_20s.wav，仅用于试听，不能代替上面的源目录。

3. 确认降噪算法

按 README 安装 requirements.txt 中的依赖。内置 V1–V4 是 noisereduce 的不同参数配置；它们用于理解比较流程，不代表四个独立训练模型。首页“降噪算法”应显示已就绪。

GTCRN / DeepFilterNet3 属于其他可选 Provider，不是首次内置比较的必需条件。

4. 准备 AudioBox 评测模型

按仓库 models/README.md 获取 facebook/audiobox-aesthetics checkpoint，并遵循其许可。放入 models/audiobox-aesthetics/checkpoint.pt；也可以在 .env 中通过 AUDIOBOX_CHECKPOINT 指定本机文件路径，然后重启服务。

模型文件不随仓库分发。首页显示就绪后，再执行真实推理；首次加载需要等待，CPU 速度取决于设备。

5. 运行、复核、确认

  1. 回首页点“重新检查”，四项应全部就绪。
  2. 开始内置 V1 → V2 比较，进入验证工作台运行；观察进度，等待真实评分。
  3. 先看本轮结论，再查看场景证据与 A/B 试听。没有运行产生的数据时，页面应显示缺测。
  4. 人工复核后再确认写入实验历史。未确认的建议只是临时结果，不等于已晋级。

DeepSeek 归因建议是可选项，不代替工程判据和人工决定。安装或准备失败时，保留错误文本，按首页缺项逐项处理；不要用合成占位分数绕过检查。
