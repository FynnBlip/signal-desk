# 08 真机采集 · 验收清单（Definition of Ready）

判据只有一句：**能不能先在一个最小范围里证明「这次采集是可信的」**。
下面每一项都要能在 10 分钟内亲手复现，不接受「理论上支持」。

## A. 链路（必需）

- [x] `python -m unittest discover -s tests` 全绿（18 项）。
- [x] `python scripts/verify_capture.py` 输出 4 个模块级场景全 PASS。
- [x] `python scripts/verify_capture.py --http http://127.0.0.1:8091 --token <t>` 输出 3 个 HTTP 场景 + 音频回读全 PASS。
- [ ] **真机**：手机扫码打开采集页，能授权麦克风、能录满 3 段脚本、能封存并看到等级。
- [ ] 采集页在非安全上下文下**主动拦下**并给出三条解法，而不是让用户对着一个没反应的按钮点。

## B. 保真度（这是本模块存在的理由）

- [ ] 手机内置麦采集时，页面显示的 AEC / NS / AGC 实际值全为 `false`，等级为 `grade_a`。
- [ ] 故意用一台强制开启 NS 的设备（或 iOS 视频通话模式）采集，等级必须落到 `grade_c`，并被拦在比较之外。
- [ ] 浏览器不回报处理链状态时，等级落到 `grade_b` 且原因写明「实际状态未知」——**不允许出现「未知但判 A」**。
- [ ] 拔掉网络再重连，序号断档是否被如实计入 `chunk_gap_count` / `dropped_frames`（不允许静默补齐）。

## C. 尺子的一致性

- [ ] 同一台手机、同一路径，连续采两次同一句 anchor，`wav_sha256` 不同但 `rms_dbfs` 与 `hf_ratio_db` 差异可解释（网络与时钟不可复现是正常的，静默漂移不正常）。
- [ ] 蓝牙耳机采集的 `hf_ratio_db` 明显低于内置麦，且 `declared_route` 与实际指纹一致；不一致时 Trace 里对得起来。
- [ ] 手动把 `declared_route` 填成 `phone_internal` 而实际用蓝牙，事后能用 `hf_ratio_db` 看出矛盾。

## D. 与 Loop 的边界

- [ ] `POST /api/capture/tier-gate` 混用 `synthetic_tts` + `real_device` 时返回 `allowed=false`。
- [ ] 真机语料不出现在 `data/matrix/`，也不参与任何晋级判定。
- [ ] `POST /api/capture/validity` 对一组同向 ΔPQ 返回 `agree_ratio=1.0`，对反向返回 `false` 并给出「生态效度存疑」。

## E. 安全与隐私

- [ ] 未带令牌访问任一 `/api/capture/*` 返回 401。
- [ ] `session_id` 含 `../` 被拒（`400`），不能读到项目文件。
- [ ] Trace 里没有真人姓名，只有 `speaker_code`。
- [ ] `consent.allow_public_share` 默认为 `false`。

## F. 一个「最小纵向闭环」的证据（对外发布前必须做掉）

目标是**一条**能端到端讲清楚的链路，而不是七块各 70%：

- [ ] 2 个输入路径（内置麦 + 蓝牙）× 3 段脚本 × 2 个降噪版本
- [ ] 走完：真机采集 → 降噪 → 评测 → Gate → 人工盲听 → 晋级/回滚留痕
- [ ] 输出一份可审计报告，明确写出：这次结论建立在什么设备、什么等级、多少丢帧之上
- [ ] 报告里必须有一行「本次测量可信度」：`grade_a` 会话数 / 总会话数，以及 anchor 重复采集的电平离散度

## 已知边界（不是缺陷）

- 实时回环试听（边说话边听 DUT 输出）未实现，属 V0.2。
- `hf_ratio_db` 是**启发式带宽指纹**，不是编解码识别，不能单独作为路径判定结论。
- 模块只保证输入侧可标定；ΔPQ 的 test-retest 稳定性需要 06 评测跑完才能给出。
