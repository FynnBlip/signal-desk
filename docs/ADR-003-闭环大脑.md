# ADR-003 · 闭环大脑（07 · LOOP）第一版方案

状态：已确认（与峰哥 grill-me 对齐）
日期：2026-08-20

> 2026-08-24 产品语义修订：Loop 不再作为与 01–06 平级的“第七个工具”，而是整个受控实验的外层结构。代码目录 `07_loop` 为兼容既有插件契约继续保留；新手界面只暴露“固定测试矩阵、当前基准版本、待验证版本、人工确认”四个概念。

## 背景

前六块（语料 → 音色 → TTS → 信道 → 降噪 DUT → 评测）已经各自可独立运行。
07 要把它们串成「闭环一」——降噪 DUT 的归因 → 迭代 → 判定 → 金标验收，
让 通话评测实验室 成为一个真正的 Agent 工作台，而不是只展示评测结果的报告。

## 决策

1. **范围**：只做闭环一（降噪 DUT 迭代）。闭环二（弱簇补语料/音色）留后续。
2. **运行形态**：人在环。每轮由大脑给出「归因 + 建议」，用户确认/驳回后执行。
3. **决策主体**：混合。判定 / 早停走规则（可复现护栏）；「下一步换什么 / 是否无解」交给 LLM。
4. **动作空间**：换模型（模型池预留）。候选试完仍无解 → 输出诚实「无解」结论，不硬跑。
5. **回归矩阵**：可配置。默认「噪声 6 场景 × 算法 2 版本」二维，语料/音色各固定 1，需要时放开。
6. **判定口径**：常规工况（SNR ≥ -5dB）通过但极端高噪档回退时，只能进入独立的“条件晋级”状态；必须由人工点击明确的条件确认动作，且历史不得记成无条件晋级。场景 dB 仅为参考标签，数字混音以 SNR 为准。
7. **金标**：轻量 A/B 试听 + 主观打分 + 状态灯；单评分者、demo 性质。
8. **可视化**：结论条先行 + 噪声 × 版本 ΔPQ 折线（标最优）+ 迭代 changelog。
9. **结论产物**：每轮落 `loop_status.json`（前端数据源）+ 人可读 Markdown 报告。
10. **LLM 契约**：输入「归因矩阵 + 判定 + 模型池 + 历史」，输出结构化 `{action, model?, hypothesis, reason}`，
    通过 function calling 调工具执行；模型用 DeepSeek（deepseek-v4-pro，`api.deepseek.com/anthropic`），
    未配 key 时回退到规则决策，保证 demo 可跑。

## 贯穿原则

- 每个 part 独立可运行，也能串成 loop。
- 文案走朴素逻辑：行内的人看得到口径，行外的人能看懂「控制变量 / 放开两个成矩阵」。
- 数据诚实：无解就写无解，不造晋级假象。
