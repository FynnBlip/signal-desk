# 交接文档 · Signal Desk

> 给「新会话 / 新模型」快速接手的交接棒。新会话先读这个 + `git log`，就能进入状态。

## 项目是什么

Signal Desk 通话评测 Agent 工作台，纯 CPU、零 GPU。把「语料 → 音色 → TTS → 信道 → 降噪 → 评测 → 判定」七步通话测试链路做成可交互的本地 Web 工作台。

- 目录：`D:\通话评测agent\signal-desk`
- 启动：`python server/main.py`，端口 8090
- 前端：`app/index.html`（单文件，总览 + 7 个模块下钻）
- 后端：`server/main.py`（FastAPI，把 modules 挂成 HTTP 接口）
- 七块：`modules/01_corpus` ~ `modules/07_loop`

七块都有可跑的最小闭环：

## 已锁定的实验与结果口径

- 声线基线是 26 个真实可用普通话系统音色，同一固定探针，固定 K=4 锚定簇；当前簇规模 C1–C4 为 10/7/5/4，后续版本映射固定簇中心，禁止每轮重聚类漂移。
- 完整赛马评分对象：26 干净音色 + 26×6=156 退化音频 + 156×4=624 DUT 输出，共 806 个；V1 vs V2 单轮共 494 个。这里是评分对象数，不是 UI 行数或每轮新生成文件数。
- 场景固定权重：安静·公园 25%、办公室 25%、咖啡厅 20%、食堂 15%、路口·交通 10%、地铁·高噪 5%；关闭场景后剔除并对剩余权重归一化。
- 每个音色等权，因此簇按 10/26、7/26、5/26、4/26 自然加权，不强制每簇 25%。
- 结果页顺序：推荐版本/原因/风险 → 六场景小多图（V1–V4 × C1–C4 的 ΔPQ）→ 折叠的 26 音色、音频和完整评分证据。
- 已落盘的 tournament rows 是耐久证据；权重或展示逻辑修改时只重算派生结论，不重跑音频。最近一次临时预览保存在 `data/loop/last_preview.json`，服务重启会恢复。

## 当前架构事实

- 七槽 Provider 目录来自 `manifest.py`，由 `/api/providers` 自动发现；HTTP 执行适配器仍显式写在 `server/main.py`。
- 后台正式 Run 在 `data/runs/`；07 临时跑轮按产品约定只在内存，人工确认后才写正式历史。
- 视觉唯一依据是根目录 `design.md` / `tokens.css`；`docs/design-*` 的 Aurora 内容是已废弃历史。

## RC 自验结果

- `unittest`：9/9 通过（评测语义迁移、Gate、Trace schema、Run 恢复、Provider 与 HTTP 输入合同）。
- 真实链路：1 条信道仿真 → 1 条 noisereduce → AudioBox 目录评测 3 条，输出与 SHA-256 Trace 均落盘。
- 异常路径：非法码率不再产生 500；空目录不创建垃圾 Run；不存在目录进入失败态；并发二次启动被拒绝。
- 重启恢复：评测 Run `20260824-025911-8c6151c7` 在服务重启后恢复为 `done`，3 条真实结果、综合分为空、等级为“未分级”。
- 闭环预览：6 个场景中 5 个常规样本，v3 因平均 ΔPQ、回退比例、最差场景三项失败被 Gate 拒绝；只生成建议，未代替人工确认。
- 响应式：总览 / 声线 / 评测 / 闭环在 768 / 414 / 375 / 320px 共 16 个组合无根级横向溢出、无浏览器错误。
- 人工验收：按 `docs/验收清单.md` 用 10–15 分钟从首页走到闭环。
