# 通话评测实验室 · 体验验收清单

按真实任务验收；页面入口为 `/` 或 `/lab.html`，模块通过侧栏进入。优先使用缓存或明确的本地夹具；例行验收不触发付费 TTS、正式评测或人工晋级。

## 1. 启动与首次准备

- 双击 `启动.bat`，健康检查通过后自动打开浏览器。关闭浏览器不等于停止服务；服务未运行时按启动说明恢复。
- 新工作区没有历史结果，不能出现别人的得分、虚假基准或虚构进度；已有工作区要标明历史轮次与当前任务。
- 首页能找到“配置与运行”，侧栏指出当前位置，七个模块均能打开并返回总览。
- 首次准备顺序为：01 语料 → 03 TTS → 02 聚类和锁定参考集。编号是模块标识，不是执行顺序。
- TTS 页可选择缓存、查看调用量预览。取消预览不发送生成请求；补齐只处理缺少的音色。输入错误、Provider 未就绪时给出明确原因。

## 2. 声线与场景

- 声线页显示当前资源、完成数量和锁定状态。已锁定资源的设置可展开，未锁定时准备/聚类入口直接可见。
- 每个三维点对应真实缓存音色；使用 PCA 时说明维度和解释方差，不写成分类准确率。各轴统一缩放，不为了视觉分离修改簇或造点。
- 拖动旋转、重置、簇聚焦、显示全部可用；聚焦允许继续点选淡化的其他簇。点选后显示匹配的名称、指标和音频。
- 在普通浏览器验证真实缓存音频能播放、暂停、拖动；簇聚焦不重建正在播放的播放器。保持原生音频控件。
- 六场景颜色在总览、信道、表格和试听上下文中一致。环境声级标成“参考/约”，不能当作实测声压或数字文件音量；设定/实测 SNR 仍保留在实验记录中。

## 3. 配置、运行与反馈

- “配置与运行”显示音色、噪声、降噪和评测就绪情况。缺项不假装就绪，并能找到准备指南。
- 选择合法的两个版本；运行中不能重复提交。真实状态反馈与后端 job/Trace 对应，不能用演示动效充当进度。
- 用本地夹具验证延迟响应、失败、取消、重试、断线恢复，不重发状态不确定的请求。
- 准备过程优先复用 TTS 缓存；正式付费调用和不可逆操作需要明确授权。

## 4. 结果与人工确认

- 总览结论、六场景和详情对应相同轮次/比较来源，历史结果与待复核结果分开。
- PQ 为主要客观指标；不擅加综合等级，不修改现有 Gate 规则。
- 基准和候选的场景均值来自同一批有效配对样本；缺测/失败与真实 0 分区分。配对数、缺测数及回退分母一致。
- “听审与迭代”提供少量建议试听和全部样本检索；A/B 身份保持盲化，记录听感不会自动晋级。
- Gate 限定可执行动作，LLM 仅建议。最终确认前若结果变化，应阻止提交；未确认结果不能进入正式历史。

## 5. 架构与报告

- 总览保留可见的架构预览，展开后可播放、暂停、重播。折叠或离开总览应暂停，减少动态效果偏好下不自动播放。
- 架构示意不宣称本机实时就绪数量；预录视频中的数字必须说明是示例。独立交互图解释 TTS→聚类与后续流程；实际任务状态从工作台/Trace 查看。
- 实验历史可展开轮次摘要与全部证据；报告先展示摘要表格，提供 Excel、Markdown 下载并解释范围。
- Excel 的轮次/样本、版本、分数及缺失值与报告范围一致，文件可打开；不只验证下载按钮能点击。

## 6. 发布关口

- 在典型桌面和较窄桌面检查遮挡、横向溢出、焦点与文字层级，记录实际生效的视口。
- `python -m unittest discover -s tests -v`、适用 Node 测试及 `python scripts/check_release_tree.py` 通过；测试不能替代真实媒体播放与界面检查。
- 缺失任一正式架构资产时发布检查应失败；新加入的文本文件也纳入凭据扫描。`.env`、音频缓存、模型权重和验收日志不能入库。
- 干净环境依照 README 首跑、普通浏览器媒体检查、远端提交一致性分别记录。未完成项明确标为未验证，不写“全部通过”。

## 已知能力边界

- Audio Judge 是预留插槽，不以 DNSMOS/NISQA 冒充已接入。
- 语料覆盖标签不等同于自动音素分析。
- 新 Provider 仍需要适配器及执行层接线，不承诺输入任意 API 地址就能使用。
- 有缓存的本机验证不等于新用户已经获得测试音频、噪声和模型资产。
