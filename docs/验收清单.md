# 通话评测实验室 · 体验验收清单

这是一条 10–15 分钟的人工验收路径。重点不是把每个按钮都点一遍，而是确认一个第一次接触通话评测的人，能否理解流程、看到依据，并知道哪些结果已经留痕。

## 0. 启动前

- 双击 `启动.bat`，浏览器应在健康检查通过后自动打开。
- 顶栏应显示「服务在线」；页面不应出现持续转圈或空白主区。
- 如果 MiniMax、某个降噪模型或 Audio Judge 未配置，对应 Provider 应显示未就绪，不影响其他槽位独立使用。

## 1. 首页：先理解，再操作

- 标题、简介、七槽链路在首屏内形成清晰主次；七个槽位可逐个进入。
- 首页应把「模块可用」「持续完善」「当前运行」分开表达，不把 wip 写成 ready。
- 「最近判定」若来自 Gate v2 之前，应明确显示「旧判据历史」，不能让人误以为它符合当前 Gate。
- 点击 01–07，确认每页标题与上下文条都能回答：输入是什么、做什么、输出什么。

## 2. 声线：从 voice_id 到固定 C1–C4

- 进入「02 声线」，先看 Cohort，而不是把每条 TTS 名称当作回归类别。
- 初始批次、固定探针、聚类版本和 C1–C4 应能对应起来；历史版本不应重新漂移簇编号。
- 在簇级回归区切换 C1–C4，能看见基线、候选和版本历史；没有数据时明确显示缺测，不造结果。
- 试听用于理解簇，不要求每轮把所有样本听完。

## 3. 评测：看懂四个轴与 Run

- 进入「06 评测」，最近一次真实结果应自动恢复。本机 RC 验收 Run 为 `20260824-025911-8c6151c7`（3 条 wav）；新环境以页面显示的最新 Run 为准。
- 「数据明细 / 统计摘要 / 可视化」三种视图应表达同一批结果，Run ID 保持一致。
- PQ = 制作质量；PC = 制作复杂度，不是越高越好的质量轴；CE / CU 分别描述内容愉悦度与实用性。
- 默认不显示综合质量分和等级；除非用户显式选择并能解释公式。
- 目录评测不填目录时，前端应直接提示「请选择快捷目录，或输入一个包含 wav 的目录」，不创建垃圾 Run。
- 运行中再次启动，后端应拒绝为「评测进行中」；刷新或重启服务后，最近完成的 Run 应恢复。

## 4. 闭环：先 Gate，后建议，最后人工确认

- 进入「07 闭环」，区分「临时预览」与「正式历史」；预览不会自动写入正式轮次。
- 查看本轮的平均 ΔPQ、常规场景回退比例、最差场景和样本有效性，能明确知道每个 Gate 为什么通过或失败。
- LLM 只能做归因与给建议，不能绕过确定性 Gate，也不能替用户确认晋级。
- 可做盲听并记录 A / B / 持平；不想形成正式历史时，不点击最终确认。
- 旧轮次应带「旧判据」标记，并说明它只保留历史事实，不代表按 Gate v2 仍会晋级。

## 5. 异常与安全边界

- 非数字码率等非法信道参数应在执行前被拒绝，不能产生 500。
- 不存在的评测目录应进入明确失败态，而不是显示「完成」。
- 试听与音频下载接口只允许预期目录内的安全文件名；路径穿越请求不得读到项目文件。
- 连续点击运行不能产生两个并发任务；按钮运行态、进度、完成或失败必须可观察。

## 6. 验收通过标准

- 新手能用自己的话复述七槽链路，以及「固定槽位、槽内 Provider 可替换」的含义。
- 有经验的用户能独立进入任一槽位，并辨认真实产物、Run、Trace、判据版本和人工确认边界。
- 页面无根级横向滚动、无控制台错误、无假数据、无把旧判据冒充当前结论的表述。
- 一次运行失败后可继续操作；一次服务重启后，最近正式 Run 仍可追溯。

## 已知边界（不是本轮缺陷）

- Audio Judge 只有热插拔槽位，尚未选定并接入新的听音模型；当前不以 DNSMOS / NISQA 代替。
- 01 的覆盖标签仍是人工语料设计标签，不等同于自动音素分析。
- Provider 元数据已自动发现；执行层尚未做到新增 Provider 后完全零改 `server/main.py`。
