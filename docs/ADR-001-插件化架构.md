# ADR-001 · 一切皆插件：Signal Desk 架构宪法

状态：v0.2 已落地，执行路由仍在收口（2026-08-24）

## 背景

峰哥在立项前就想好「接口大于实现、模块可替换」（旧项目思维导图：SCPI / MCP 思想）；
DeepSeek Harness 的「一切皆插件」与 Cordis 元框架是同一哲学的官方印证。
本 ADR 把该思想固化为 Signal Desk 的架构宪法。

## 决策

### 1. 七块蛋糕 = 七个插件，统一 manifest 契约

`modules/` 下每个模块目录自带 `manifest.py`，是插件与元框架之间唯一的约定：

```python
MANIFEST = {
    "id": "02_voice",        # 唯一 id，目录名一致
    "name": "音色聚类",       # 侧边栏/卡片显示名
    "version": "0.2.0",
    "status": "wip",         # ready 可用 / wip 施工中 / disabled 停用
    "routes": [],            # 当前 HTTP 能力
    "providers": [],         # 槽内可替换实现、依赖与 capability
    "tools": [],             # 可执行动作清单
    "summary": "声线特征提取 + KMeans 聚类 + 覆盖矩阵",
}
```

- 默认实现可以烂，契约必须稳定；
- Provider 的发现、就绪状态和 capability 不改前端信息架构；执行适配器仍需在 server 注册；
- 降噪 DUT 等模块未来可换厂商 SDK，符合「一切皆插件」。

### 2. server 是元框架，分两层发现

- Provider 目录层：服务扫描 `modules/*/manifest.py`，`GET /api/modules` 与
  `GET /api/providers` 自动返回槽位、Provider、依赖、capability 与运行时就绪状态。
- 执行层：当前 v0.2 仍由 `server/main.py` 显式适配各模块 HTTP 路由。这是诚实的边界；
  “丢目录零改 server”是后续目标，不把 metadata discovery 冒充完整插件运行时。
- Run 层：产生后台任务的入口按统一 `run_id/state/progress/result/error/timestamps`
  写入 `data/runs/<kind>/`；关键请求使用 Pydantic schema 暴露 OpenAPI 契约。

### 3. 闭环走临时预览 + 人工确认后的正式历史

- 跑轮只保存在当前服务内存，重跑会替换临时预览；不把失败试点伪装成正式历史。
- 确认晋级、回滚或无解后才原子更新 `data/loop/loop_status.json` 与报告。
- 人工盲听独立 append 到 `data/loop/listening_v1.jsonl`，含 A/B assignment 与实际选择。
- 确定性 Gate 先产生 allowed actions；LLM 只能在集合内解释和建议，不能绕过守门。

### 4. 模式化加载

| 模式 | 加载 | 用途 |
|---|---|---|
| 极简 | 仅 06 评测 | 只喂 wav 出分 |
| 标准 | 01~07 全部 | 完整双闭环 |
| 演示 | 全链路 + 一键 run_demo | 面试/开源 showcase |

## 不做什么（Simplicity First）

- 不引入 Cordis / Node 插件运行时，Python + FastAPI + importlib 即元框架；
- 不抽象模型层、沙箱、调度——那是通用 agent 运行时的职责，Signal Desk 是垂直评测 agent；
- 事件流用 jsonl，不建重型事件存储。

## 与数据红线的关系

ADR 管「代码怎么长」，数据红线管「数字从哪来」。两者并列生效，互不豁免。
